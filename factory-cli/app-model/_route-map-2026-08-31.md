## Three findings from this capture

### 1. `/production-planning/` is a ghost, not a gap

The 2026-08-03 endpoint study catalogued 16 `/production-planning/*` endpoints and
`factory-cli` ships none of them, which read as the single biggest coverage hole in
the CLI. It is not a hole. **Every one of those paths returns Django's HTML 404** on
all three companies — the URL prefix is not registered on the API at all. Proof that
this means "unrouted" rather than "forbidden" or "no such row": on this same API a
live prefix with a bad sub-path (`/production-execution/definitely-not-a-real-path/`)
returns the same HTML 404, while a live route with a missing object
(`/production-execution/runs/999999/`) returns DRF JSON `{"detail": "..."}`.

The module was **replaced by `/planning-purchase/`**, which is live and carries real
data (`GET /planning-purchase/plans/` on JIVO_OIL returns "OIL Monthly Production
Planning for the Sep Month 2026"). The old constants are still in the bundle as dead
code with no UI route pointing at them, so a bundle scrape catalogues them as
surface. **Do not build commands for `/production-planning/*`.**

### 2. Three live modules the endpoint study never saw

Visible in the main bundle alone, all verified live (HTTP 200):

| Module | API endpoints in the main bundle | State |
|---|---:|---|
| `/etp/` — effluent treatment plant | 37 | deployed on all 3 companies, **all empty** — nobody has entered data yet |
| `/planning-purchase/` | 12 | live, real data |
| `/sap-reports/` | 10 | live, real data (82 queries under "APPROVAL TEMPLATES" alone) |

ETP covers daily logs, monitoring records, calibration, chemicals, sludge and
instruments — pollution-control-board record-keeping. It is built and reachable and
nothing is in it.

### 3. The main bundle is not the whole surface

It references **673 lazy chunks** that were not fetched here. `/warehouse-ops`,
`/fire`, `/returns`, `/finance` and `/daily-tasks` have UI routes in the main bundle
but zero API literals in it — their endpoint constants live in those chunks. Sizing
them needs a full chunk sweep, which is a VPS job, not a laptop one.
