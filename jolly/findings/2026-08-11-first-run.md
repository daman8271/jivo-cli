# Finding 07 — the requirement engine, built and run live

**Date:** 2026-08-11 · Jivo Oil · read-only
**Engine:** `jolly/engine/requirement.py` · **Output:** 178 SKUs

```
Production Requirement = OIH + MSL − FG − production already released   (floored at 0)
```

Settled with the operator and now encoded:

| Term | Decision |
|---|---|
| **OIH** | SAP open sales orders. OMS only pushes an order to SAP once its approval workflow completes — verified: orders sitting in OMS `Approved`/`Billing` carry **no** `sap_doc_number`, `Completed` ones do. So SAP's open orders **are** the approved orders. |
| **MSL** | 35% of the previous **calendar** month's sales. Intercompany (Oil→Mart) **counts**. |
| **FG** | **BH-BT + BH-PF only.** BH-BS and BH-PM are packaging godowns. Every other warehouse out of scope. |
| **WIP** | Open SAP production orders subtracted, with a **60-day age cut-off** — SAP carries stale open orders (FG0000030 has two at 0% since 2024-11 and 2025-06 that would have erased 18,400 bottles of real requirement). |
| **Units** | Everything in PCS (single bottles). OMS boxes convert on the way in. |
| **Floor** | Negative → 0. |

## ⚠️ The August plan is 1.8× what JIVO actually sold last month

> **CORRECTED 2026-08-12 — the conclusion in this section is wrong.** Comparing a
> full-month forecast against a full-month actual is the wrong test. Day-matched
> against the same 12 days of every prior month, August 2026 is running at
> **2.3× the previous record**, and the 4,241 MT forecast is credible. The operator
> has since confirmed the plan is a forecast, not a target. See
> **Finding 09 — `2026-08-12-forecast-tested.md`.** The paragraph below stands only
> as a record of the wrong reasoning.

| | MT |
|---|---|
| **July 2026 — actually sold** (net of returns, all Oil SKUs) | **2,344** |
| August plan — trade (GT/MT/ROI) | 1,898 |
| August plan — ecom | 2,343 |
| **August plan — total** | **4,241** |

The ecom line alone (2,343 MT) is the size of the entire company's July sales.

In a business whose stated constraint is that it **cannot get enough raw material**,
a plan set at 1.8× last month's actual throughput is not a plan — it is a wish. Every
requirement computed against it will overstate, every material shortfall it predicts
will be permanent, and people will learn to ignore the alarms.

This is worth settling before the pilot messages anybody: **is 4,241 MT a target or a
forecast?** If demand really is that far above supply, then the pilot's job is
explicitly allocation — decide which 2,300 MT gets made — and the plan should say so.

## Infrastructure note

Mid-build, the SAP box stopped answering on both HANA (30015) and the Service Layer
(50000), from this machine **and** from the VPS. SSH to the box still worked, so the
engine now runs through an SSH tunnel:

```bash
ssh -f -N -L 30016:127.0.0.1:30015 jivo-sap-any
python3 jolly/engine/requirement.py --env <tunnelled hana.env>
```

**For a pilot that must run daily and unattended, this is a real risk.** Direct DB
access to SAP disappeared without warning and nothing would have noticed. The tunnel
should become the default path, not the fallback.
