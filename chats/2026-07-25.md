## The three walls (each verified with evidence)
1. **File share is LAN-locked.** Attachments live on `\\20.20.45.25\Attachments_Oil\JIVO_OIL\Attachments` — a Windows share on the server-room LAN (20.20.x.x). Office **Wi-Fi is a different network** (192.168.1.x, egress `38.254.177.106`) with no route to it; Tailscale advertises no subnet route either. Ping 100% loss, SMB 445 closed — re-confirmed this afternoon from the Mac Air.
2. **Service Layer can't serve attachments (server-side config gap).** `GET Attachments2(155435)/$value` → 404 **"Fail to get the LINUX mount point for AttachmentsFolderPath"**. The Service Layer runs on the Linux/HANA box; the Windows attachments share was never CIFS-mounted there, so the API physically cannot stream any attachment. **Network-independent — fails identically from every machine, including office ones.** This is why the kit on the colleague's PC couldn't fetch attachments despite being "on the right network".
3. **NEW this afternoon — SAP endpoint itself unreachable.** `103.89.45.192:50000` stopped answering (ping 100% loss, port closed) from our egress IP `38.254.177.106`. Differential tests: **postsql `.76:5432` answers fine from the same machines** → office server edge is UP; failure is specific to the `.192` host. Mac Pro (same NAT) sees the same. VPS is not a valid probe (`.192` firewalls by source IP and the VPS was never whitelisted — see [[2026-07-24]] goal #85). So either the SAP box/Service Layer is down, or its per-source-IP firewall dropped our IP. **IT question, not an app problem.**

## Fixes (so this never happens again)
- **[root fix, attachments] IT mounts the attachments share on the HANA/Linux box** (CIFS-mount `//20.20.45.25/Attachments_Oil` + let SL resolve `AttachmentsFolderPath`). Quote SAP's own error; ~5-min job. Makes every attachment downloadable via the API we already use, from anywhere, for everyone.
- **[root fix, reachability] Tailscale subnet router at the server site** — one always-on office machine advertises `20.20.45.0/24` (+ ideally the SAP server's internal subnet). Ends both the share-unreachable problem and the fragile public-IP/firewall-whitelist dependency.
- **[resilience] Stop depending on the `.192` public endpoint + per-IP whitelist** — whitelist stable IPs (VPS `187.127.129.132`, the standing goal-#85 ask) or move SAP access onto the tailnet; broadband egress IPs rotate.
- **[monitoring] Health check** — once a whitelisted stable vantage exists, cron a 5-min `sapb1 doctor`-style probe + alert, so "is it the app or the server?" is answered instantly.
- **[security, rollout] Read-only SAP user before spreading the kit** — the accounts-kit `.env` carries `manager` creds; every install (e.g. the colleague's PC) is another copy. Already flagged 2026-07-24, now urgent.
- **[hygiene] Push the stranded morning log** (goal #87) from the other laptop.
